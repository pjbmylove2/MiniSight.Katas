# VS2022 디버깅 치트시트

## 1. 단축키

| 키 | 기능 |
|---|---|
| F5 / Ctrl+F5 | 디버깅 시작 / 디버거 없이 시작 |
| Shift+F5 / Ctrl+Shift+F5 | 중지 / 다시 시작 |
| F9 | 중단점 토글 |
| F10 / F11 / Shift+F11 | 프로시저 단위 / 한 단계씩(들어가기) / 나가기 |
| Ctrl+F10 | 커서까지 실행 |
| Ctrl+Alt+Break | 모두 중단 |
| Ctrl+Alt+B | 중단점 창 |
| Ctrl+Alt+C | 호출 스택 |
| Ctrl+Alt+H | 스레드 |
| Ctrl+Shift+D, S | 병렬 스택 |
| Ctrl+Alt+I | 직접 실행(Immediate) |
| Ctrl+Alt+E | 예외 설정 |
| Ctrl+Alt+U | 모듈 |
| Ctrl+Alt+F2 | 진단 도구 |
| Alt+F2 | 성능 프로파일러 |
| Ctrl+Alt+P | 프로세스에 연결 |
| Ctrl+E, T | 테스트 탐색기 |

## 2. 중단점 종류

| 종류 | 만드는 법 | 쓰는 곳 |
|---|---|---|
| 조건부 | 중단점 우클릭 → 조건 → `Name == "Cam2"` | 특정 장치·프레임만 |
| 적중 횟수 | 조건 → 적중 횟수 `= 3`, `>= 100` | N번째 프레임 |
| 필터 | 조건 → 필터 → `ThreadName == "..."` | 특정 스레드 |
| Tracepoint | 작업 → 메시지 `{변수}` + 실행 계속 | 멈추면 타이밍이 바뀌는 문제 |
| 종속 | 조건 → "다음 중단점에 도달한 경우에만" | A 이후 B |
| 함수 | 중단점 창 → 새로 만들기 → 함수 이름 | 소스 위치 모를 때 |
| 데이터 중단점 | (.NET Core 3+만) — .NET Framework는 불가 → 속성 setter에 중단점 | |

## 3. 값 보기

- **Autos / Locals / Watch**: 근처 변수 / 현재 메서드 전부 / 직접 지정.
- **Parallel Watch**: 스레드별 같은 식의 값.
- **DataTip 핀**: 마우스 오버 → 핀 → 루프 내내 표시.
- **직접 실행 창**: 메서드 호출 가능. Mat은 `Cv2.ImWrite(@"C:\tmp\x.png", mat)`로 파일로 떠서 보기. 작은 Mat은 `mat.Dump()`.
- **$exception**: catch 블록에서 현재 예외. **$returnvalue**: 방금 반환한 값(Autos).

## 4. 멀티스레드

| 창 | 언제 |
|---|---|
| 스레드 | 이름으로 찾기, Freeze/Thaw(race 손으로 재현), Flag(관심 스레드만) |
| 작업(Tasks) | Task 상태(활성/대기/예약), async 대기 확인 |
| 병렬 스택 (스레드 보기) | **데드락·멈춤 원인 1순위**. 대기 프레임(Monitor.Enter, Wait, Take)을 찾는다 |
| 병렬 스택 (작업 보기) | async 논리 스택 |
| 호출 스택 `[비동기 호출]` | await 경계 |

멈춤 진단 순서: 모두 중단 → 병렬 스택 → UI 스레드 위치 → 대기 중인 대상(lock/Task/큐) → 그걸 쥔 스레드.

## 5. 예외

- 예외 설정에서 체크 = **throw 순간**(first-chance)에 중단. catch로 처리되는 예외도 잡힘.
- 평소엔 `OperationCanceledException`/`TaskCanceledException`은 끄고 다님(정상 흐름).
- "내 코드만(Just My Code)": 도구 → 옵션 → 디버깅. 프레임워크 내부 보려면 끄기.
- WinForms 크로스 스레드 검사는 디버거 연결 시에만 예외로 나타남.

## 6. 메모리·성능

| 도구 | 방법 | 찾는 것 |
|---|---|---|
| 진단 도구 → 메모리 사용량 | 스냅숏 2개 → 개체(차이) → 루트 경로 | Mat/Bitmap 개수 증가, 누가 잡고 있나 |
| 성능 프로파일러 → CPU 사용량 | **Release**로 측정, 상위 함수·핫 경로 | 가장 비싼 함수 |
| 성능 프로파일러 → .NET 개체 할당 | 할당 많은 타입 | 프레임당 할당 |
| 작업 관리자 → 세부 정보 → 열 선택 | GDI 개체, 핸들, 스레드 | GDI/핸들 누수 |
| `Tools/Diagnostics/Monitor-OmniSight.ps1` (회사) | 프로세스 지표 CSV | 장시간 추세 |

누수 판단: 입력 고정 → 워밍업 후 기준 → 입력 정지 후 안정되는지 → 반복 동작(Start/Stop, 재연결)으로 계속 오르는 자원 찾기. `GC.Collect()`로 감추지 않기.

## 7. 네이티브·배포

- 모듈 창: 로드된 DLL 경로·비트·버전.
- 플랫폼 x64 확인 (구성 관리자, 프로젝트 속성 → 빌드 → 플랫폼 대상, "32비트 선호" 해제).
- `BadImageFormatException` = 비트 불일치, `DllNotFoundException` = DLL 또는 **그 의존 DLL** 없음.
- 프로젝트 속성 → 디버그 → 네이티브 코드 디버깅 사용 = 혼합 모드.

## 8. 여러 프로세스·현장

- 솔루션 속성 → 여러 개의 시작 프로젝트.
- 프로세스에 연결(Ctrl+Alt+P): 이미 실행 중인 exe. 원격은 "원격 도구(msvsmon)" 설치 후 연결 대상에 PC 이름.
- 덤프: 디버그 → 덤프를 다른 이름으로 저장(힙 포함) / 작업 관리자 → 덤프 파일 만들기 → VS에서 열기 → 관리 전용으로 디버그 → 스레드·병렬 스택.
- 심화: WinDbg + SOS (`!threads`, `!clrstack`, `!syncblk`, `!dumpheap -stat`).

## 9. 테스트

- 테스트 탐색기 → 실패 테스트 우클릭 → 디버그.
- 테스트 설정 → 프로세서 아키텍처 x64 (OpenCV).
- 동시성 테스트는 반복 실행(100회)으로 간헐 실패 확인.
