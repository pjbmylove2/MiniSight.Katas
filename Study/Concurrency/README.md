## 0. 한 장으로 보는 특강

```text
이야기: 우리는 "사과 공장"을 만든다.
  사진기(카메라)가 사과를 찍는다 → 바구니(큐)에 담는다 → 검사 일꾼들이 멍든 사과를 찾는다
  → 분류기(PLC 흉내)가 OK/NG 상자로 보낸다 → 칠판(화면)에 숫자와 사진이 보인다
  → 채점 로봇(테스트)이 "제대로 했나" 매번 확인한다

1일차  일꾼          멀티스레드 기초 + 화면 + 첫 채점 로봇    → 사과 사진이 화면에 나온다
2일차  같이 쓰기     싸움 막기(열쇠·번호표·팻말) + 줄 서기    → 사과가 줄 서서 검사되고 숫자가 올라간다
3일차  나눠서 빨리   병렬처리 + 기다리기(async) + 취소         → 일꾼 1·2·4명 속도표가 화면에 나온다
4일차  고장 찾기     데드락·조용한 고장·감시견 + 동시성 테스트  → 작품 PipelineLab v1 완성 + README
```

|---|---|
| 멀티스레드 | 1~6, 9~14, 20~22, 25~27, 29 |
| 병렬처리 | 17~19, 23~24 |
| 테스트 | 7, 15, 28 (그리고 작품을 만들 때마다 조금씩) |

## 1. 진행 방식 (1학년 규칙)

- **1교시 = 50분 + 쉬는 시간 10분.** 교시 하나에 **조각 2~3개**를 한다.
- 조각마다 순서는 같다:
  1. 🧒 **비유 한 줄** (사과 공장 이야기로)
  2. **10~15줄 코드**를 보면서 친다 → 실행한다
  3. **처음 보는 단어 표** (뜻 / 쓰는 법)
  4. **눈으로 보는 실험 1개**
  5. **확인된 예상 출력** (Claude가 미리 컴파일·실행해 본 것)
  6. **질문 1개** (빈칸 채우기로 시작해도 된다)
- 한 줄 `if`에도 `{ }`. 약 70%면 넘어간다. 남은 건 PROGRESS "다시 물어볼 질문"에 적는다.
- 답은 **"무엇을 → 그래서 무슨 일이"** 두 토막으로 말하는 연습을 한다 (지금까지 가장 자주 빠진 부분).
- 코드가 남는 곳:
  - 연습 조각: 포트폴리오 `Katas/Concurrency/KataPNN.cs` (PNN = 교시 번호), 조각마다 `ChunkN()`. **"전부 지우고"는 없다.** `Program.cs`는 그날 교시의 `KataPNN.Run()`만 부르고, 나머지는 주석으로 둔다.
  - 작품: 포트폴리오 `PipelineLab/`(WinForms) + `PipelineLab.Tests/`(MSTest). 교시마다 조금씩 붙인다.
- 버전은 **.NET Framework 4.7.2 / C# 7.3 / WinForms / x64**. 새 NuGet 패키지는 쓰지 않는다.
- 교시별 상세 내용은 그 교시를 할 때 채팅으로 진행하고, 하루가 끝나면 `Concurrency/Day-A.md`~`Day-D.md`에 조각 형식으로 모은다 (Day01.md 템플릿).

## 3. 작품 · `PipelineLab` v1 (사과 공장 검사기)

> 한 줄 소개: **가짜 사진기 여러 대가 찍은 사과를 여러 일꾼이 나눠 검사하고, 처리량·바구니 높이·버린 수·일꾼 상태를 실시간으로 보여 주고, 고장을 일부러 넣으면 감시견이 잡아내는 WinForms 프로그램.**
> 포트폴리오에서는 "동시성을 숫자로 설계하고 테스트로 증명한다"는 증거, 현장 이야기로는 "이 PC로 초당 몇 장까지 버티나"를 보여 주는 도구다.

### 3-1. 화면

| 영역 | 내용 | 몇 교시에 생기나 |
|---|---|---|
| 도구 모음 | 시작 / 정지, 사진기 수(1~4), 초당 장수, 검사 일꾼 수, 바구니 크기, 꽉 찼을 때 정책 | 5, 14, 23 |
| 사진 창 | 사진기마다 최신 사과 1장, OK는 초록 테두리 / NG는 빨간 테두리 | 6, 12 |
| 칠판(대시보드) | 찍은 수, OK/NG 수, 버린 수, 잃은 수(0이어야 함), 바구니 높이, 걸린 시간, 일꾼 수별 속도표 | 11, 14, 24, 30 |
| 장애 버튼 | 검사 느리게, 검사 중 예외, 팻말 안 되돌리기, 교착 모드 | 27 |
| 감시견·로그 | 단계별 신호등(초록/빨강), 로그 파일 | 27, 30 |

### 3-2. 다 됐다고 말하는 기준 (측정으로 확인)

- 사진기 4대 × 초당 30장에서 **화면이 멈추지 않는다.**
- "막기" 정책으로 10분 돌려서 **잃은 수 0, 중복 0, 순서 뒤바뀜 0** (번호표로 센다).
- 일꾼 1·2·4명 속도표가 README에 있다.
- 장애 버튼 4개를 각각 눌렀을 때 감시견이나 로그가 잡아낸다 (GIF).
- 정지 버튼을 누르면 **2초 안에** 모든 일꾼이 퇴근하고, 사진 반납 수 = 만든 수.
- 채점 로봇(MSTest) **8개 이상이 모두 녹색**.
- 처음 보는 사람이 README만 보고 실행할 수 있다.

### 3-3. 지킬 것

- 회사·고객사·현장·설비·벤더 이름, 회사 코드, 실제 PLC 패킷·IP·경로를 쓰지 않는다. 사진기와 분류기는 모두 **가짜**다.
- 새 NuGet 패키지 없이 만든다. 사과 그림은 `Bitmap`으로 직접 그린다.
- 업로드(GitHub·블로그)는 사용자가 요청할 때만 한다.

## 5. 2회차에 볼 것

1회차가 끝나면 교시별 "70% 통과 / 남은 질문", 시간이 모자랐거나 남았던 교시를 보고 다시 짠다. 2회차 후보는 이렇다: 메모리 모델과 캐시(false sharing), 스레드 풀 내부, 잠금 도구 전부 비교, PLINQ, async 내부(상태 머신), UI 교착, lock-free, 성능 도구(Concurrency Visualizer, PerfView), WinDbg.
