# 3단계 · 시니어 트랙 (S01~S12)

> 시작 조건: [주니어 졸업 기준](../00-Roadmap.md#2단계--주니어-프로그램을-만든다-day0128-2회차)을 통과했다.
> 목표: "코드를 짤 줄 안다"에서 **"장비가 멈췄을 때 혼자 원인을 찾고, 고치고, 보고하고, 다른 현장에 옮길 수 있다"**로 올라간다.

## 1. 진행 방식

- 단원 하나는 평일 2~3일 분량이다. **일주일에 2단원**, 약 6주.
- 상세 문서(`S01-*.md` 등)는 단원을 시작할 때 Claude와 함께 만든다. "S01 시작"이라고 말하면 된다.
- 초급·주니어와 같은 규칙을 지킨다: 키워드 표, 한 줄 `if`에도 `{ }`, 작은 조각, 약 70%면 넘어가고 남은 건 PROGRESS에 적는다.
- 장비가 없으니 **시뮬레이터, 가상 포트, 일부러 만든 장애**로 연습한다. 그래서 결과물마다 "어떻게 재현했는지"가 같이 남는다.
- 시니어 단계의 결과물은 대부분 **문서와 증거**다(보고서, 그래프, 체크리스트, CI 배지). 면접에서 그대로 보여 줄 수 있게 만든다.

## 2. 단원

### S01 · 표준 PLC 프로토콜 (Modbus TCP)
- **왜**: 현장마다 프로토콜은 다르지만 "주소 체계, 워드/비트, 읽기·쓰기 명령, 예외 응답"이라는 뼈대는 같다. 하나를 직접 구현해 보면 나머지는 문서만 읽고 붙일 수 있다.
- **최소**: FC03(Holding Register 읽기), FC06(단일 쓰기)을 `TcpClient`로 직접 구현하고, 직접 만든 시뮬레이터와 통신한다.
- **결과물**: `ModbusClient`, `FakeModbusServer`, 패킷 단위 테스트, Wireshark 캡처 1장.
- **연결**: B10(바이트·엔디언), Day22(프레이밍·재연결).

### S02 · 시리얼 통신
- **왜**: 조명 컨트롤러, 바코드 리더, 오래된 센서는 아직 RS-232/485다.
- **최소**: 가상 COM 포트 쌍(예: com0com)을 만들고 `SerialPort`로 조명 밝기 설정 명령을 주고받는다. 보레이트·패리티를 일부러 틀려 본다.
- **결과물**: `SerialLightController` + "통신이 안 될 때 확인 순서" 체크리스트.

### S03 · 장애 재현 실험실
- **왜**: 현장 장애는 재현할 수 없으면 고쳤다고 말할 수 없다.
- **최소**: MiniSight에 데드락 1개, Mat 누수 1개를 일부러 넣는다 → 작업 관리자로 덤프 생성 → VS로 열어 원인 줄을 찾는다.
- **결과물**: 장애 보고서 2편(현상 → 영향 → 원인 → 조치 → 재발 방지, 타임라인 포함).
- **연결**: Day14(데드락), Day15·18(Mat·Dispose), FieldSkills F03·F04·F07.

### S04 · 장기 구동(soak) 테스트
- **왜**: "며칠 돌면 죽는 프로그램"은 짧은 테스트로는 안 잡힌다.
- **최소**: 가짜 카메라로 12시간 구동하며 메모리·핸들 수·GC 횟수·처리 시간을 1분마다 CSV로 남기고 그래프로 그린다.
- **결과물**: 구동 리포트(추세 그래프 + 판단 기준 "이 정도면 누수").

### S05 · 성능과 택트
- **왜**: 라인 속도를 못 따라가면 검사가 빠진다. 감이 아니라 숫자로 말해야 한다.
- **최소**: 단계별 처리 시간 측정 → VS 프로파일러로 병목 1개 찾기 → 버퍼 재사용 등으로 개선 → 전후 비교.
- **결과물**: 택트 예산표(촬영 · 전처리 · 판정 · 송신 · 여유), 전후 비교표.

### S06 · 카메라·조명·광학 계산
- **왜**: 카메라를 고르거나 프레임 드롭을 설명할 때 계산이 먼저다.
- **최소**: 대역폭(해상도 × fps × 비트), FOV와 분해능(mm/px), 하루 이미지 저장 용량을 계산하는 작은 도구를 만든다.
- **결과물**: 현장 계산기(콘솔 또는 WinForms) + 예제 3개(에어리어, 라인 스캔, 고속).

### S07 · 배포·운영
- **왜**: 새 버전이 현장에서 안 되면 5분 안에 되돌려야 한다.
- **최소**: PowerShell로 설치 → 업데이트(이전 버전 백업) → 롤백 스크립트를 만들고, 버전·설정 백업을 남긴다.
- **결과물**: `deploy/` 스크립트 + 장비 PC 세팅 체크리스트(절전, 업데이트, 시작 프로그램, 권한, 시간 동기화).

### S08 · 품질 자동화 (CI)
- **왜**: "내 PC에선 됐어요"를 없앤다.
- **최소**: GitHub Actions(Windows 러너, MSBuild)로 push마다 MiniSight 빌드와 MSTest 실행.
- **결과물**: README의 CI 배지, 실패한 빌드를 고친 기록 1건.

### S09 · 레거시 이식과 동작 보존
- **왜**: 현장 리팩토링의 핵심은 "구 버전과 결과가 같다"는 증명이다.
- **최소**: MiniSight 필터 체인을 리팩토링하기 전에 골든 이미지·결과를 저장하고, 리팩토링 후 자동 비교한다.
- **결과물**: 골든 테스트 세트 + "동작 보존 리팩토링 절차" 문서.

### S10 · 현장 문서
- **왜**: PLC 담당자, 고객과 같은 그림을 보고 이야기해야 한다.
- **최소**: MiniSight 기준 IO 맵, 트리거·결과 신호 타이밍 차트, FAT/SAT 체크리스트, 이식 체크리스트.
- **결과물**: `docs/` 문서 묶음.

### S11 · 설계 결정과 가르치기
- **왜**: 시니어는 혼자 잘하는 사람이 아니라 결정을 남기고 남을 키우는 사람이다.
- **최소**: MiniSight에 기능 1개(예: 검사 결과 CSV 보고)를 요구사항 → ADR → 구현 → 셀프 리뷰 순서로 넣는다. 기초 Kata 하나를 후배용 30분 강의 자료로 다시 쓴다.
- **결과물**: ADR 3편, 강의 문서 1편.

### S12 · 시니어 졸업
- **최소**: MiniSight v1.0 태그와 릴리스 노트(설치·롤백 방법 포함), 아키텍처 문서, 데모 GIF, 모의 면접(장애 시나리오 1개 + 이식 시나리오 1개).
- **결과물**: GitHub Release, 정리된 포트폴리오 README.
